The task is QA v12 after PR #289. Its immutable acceptance contract defines
Planner, Builder and Inspector only. QA and security therefore need a separate
approved scope; the remaining USD 0.13840 under the previous ceiling is not an
allowance for additional calls. Existing receipts, reservations and identities
remain unchanged.

The next concrete deployment is identity bootstrap only:

- Stack: `tims-factory-review-bootstrap`, account 666730517561, ca-central-1.
- Twelve new resources: two Ed25519 KMS keys, two aliases, two Lambda execution
  roles, two 14-day log groups, two functions and two immutable versions.
- Functions: `tims-factory-review-qa` and `tims-factory-review-security`.
- Each execution role can sign only with its own key and write its own logs.
  A key-policy deny prevents other principals from signing with that key.
- The handler accepts only a nonce-bound, five-minute identity challenge tied
  to the exact deployed source. It rejects work requests before creating AWS
  clients. It checks the actual assumed-role identity and verifies the returned
  signature locally. All SDK clients disable retries.
- No public endpoints, invocation grants to the controller, state/database
  access, provider access, secret access, schedule, operational signing-key
  enrollment, verdicts or release permissions are included.

The reviewed template is `infra/roles/review-bootstrap.cloudformation.json`,
generated by `scripts/prepare_review_role_bootstrap.py`. Build the clean Linux
package with `scripts/build_review_roles_package.py` into a directory outside
the checkout, then bind its immutable S3 version and code SHA256 at deployment.
Validate the change set contains only the twelve expected Add operations.
Deployment requires approval before execution. Afterward, invoke exactly one
synchronous identity probe per role with no retries; verify the returned
signatures against public keys independently retrieved from the exact stack
outputs. Unknown outcomes require inspection, not another invocation.

AWS lists customer-managed KMS key storage at USD 1/key/month, prorated hourly:
https://aws.amazon.com/kms/pricing/
Two retained keys therefore add approximately USD 2/month, plus metered KMS,
Lambda, logs and S3 usage. This is separate from model budgets. Keys are retained
on stack deletion; deleting a stack does not stop their storage charge. Disabling
keys is reversible but also does not remove storage charges. Any permanent key
deletion needs separate approval. No keys have been created by this change.

reruns its 11 tests, then checks 41 valid inputs twice and nine invalid inputs
(91 additional executions). It inspects the exact source's import and dynamic
execution surface. These local checks are supplemental evidence, not a signed
QA/security gate verdict and not proof of filesystem sandboxing.

prepare isolated QA/security execution, exact signed job scope, durable
