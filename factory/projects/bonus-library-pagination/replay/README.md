# Real repository offline acceptance replay

`source.bundle` contains the shallow commit and complete 101-file source tree of
`timbrydges/bonus-library` at `ef88df95bc3f046d080af51e3654d2259759072b`.
It was read from that repository, not generated as a test fixture. The replay
imports Git objects locally, preserves the shallow boundary, verifies blob hashes,
and never fetches, checks out, executes hooks or accesses product services.
The integrity manifest pins the bundle bytes. Do not use it as current main.

`scripts/development_runner_replay.py` constructs a **hand-authored** proposal from
the helper and tests here plus exact dashboard replacements. A durable local queue
claim drives proposal validation, disposable candidate creation, real isolated Node
tests, a **recorded review**, and evidence persistence. A second tick must do no work.
The review is a transport/progression check, not independent model review.

Linux CI resolves a Node image and passes its immutable digest to the existing
network-disabled sandbox. Only the five pagination tests run; dependencies are not
installed inside that sandbox. Those tests use an independent in-memory relational
oracle, not a live database. The dashboard check is structural, not a browser test.
Local preparation additionally checks the candidate with pinned dependencies,
TypeScript and ESLint. No product checkout or production setting is modified.

The output contains the full proposed edits, bound sandbox request/receipt,
review packet and decisions, durable queue, and a summary clearly labelled
`OFFLINE_REPLAY_REAL_REPOSITORY`. It grants no production or release authority.
An interrupted claim or failed artifact write is never automatically retried.

## Remaining live qualification

- Connect authenticated admission and automatic credential leasing to a deployed
  composition; the offline driver does not mint authorization or credentials.
- Pin the current target, provider/model, price, allowance and test environment.
- Obtain a specific bounded live approval before real provider requests, spending,
  scheduler activation, cloud staging or access changes.
- Obtain a real independent reviewer decision and validate the rendered pagination
  flow. A recorded APPROVE is never evidence of that work.
- Produce the Bonus Library review PR; do not merge or deploy the product as part
  of this acceptance task. Existing release gates remain mandatory.

Production remains disabled; existing holds are unchanged. The runner does not
create a timer, publish a PR, sign evidence, grant access, or call a model itself.
